# 扩大 Windows 真实模型基准与失败分析

> 制定日期：2026-09-27。承接[三题试跑结果](../../reviews/0002-2026-09-27-评审-Windows真实模型基准试跑结果.md)：三题各跑一轮均成功，但任务简单，无法据此判断复杂任务的表现。

## 目标

用更多任务和重复运行，得到可复核的成功率、失败原因、耗时和 Token 用量。先继续使用 Windows、DeepSeek `deepseek-flash` 和独立临时 Git 仓库；这一轮不改变产品权限策略，也不把 Windows 宿主沙箱纳入基准结论。

## 执行顺序

1. **固定任务与判定标准。** 保留现有三题，再增加三道难度更高的任务，分别覆盖跨文件修改、Windows 路径处理、错误处理。每题预置会失败的测试、明确允许修改的文件和可独立运行的验收命令。先检查测试确实能识别目标缺陷，避免任务本身失效。
2. **完善基准记录。** 每次运行保存任务编号、代码提交、模型 Profile、CLI 退出状态、测试与改动范围、墙钟耗时、模型报告耗时、输入/输出 Token 和失败类别。失败时保留脱敏诊断，不保存 API Key。将夹具和统计改动拆成可复核的提交，并新增 `learn/changes/` 记录。
3. **重复运行。** 六道任务各运行三次，共 18 次；每次从相同的初始文件开始。若出现环境或服务中断，记录该次原因和是否重跑，不静默丢弃样本。每次运行只允许写入对应临时仓库。
4. **核对和落地结果。** 汇总按任务和按失败类型的通过次数，给出耗时、Token 的实际分布；抽查 Git 差异与测试输出，确认自动判定可信。将结果写入新的 `learn/reviews/` 文档，并在 `learn/WORKLOG.md` 用容易理解的话更新进展。代码提交后检查默认离线门禁及远端 CI。

## 完成标准

六道任务的夹具和复现命令可用；18 次运行均有记录或明确的中断原因；成功和失败都能追溯到测试及 Git 改动范围。结果文档说明样本规模、运行环境和不能推断的范围。若基准暴露产品缺陷，先新增 `learn/bugs/` 记录，再按独立工作单元修复并验证。
