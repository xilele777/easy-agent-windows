# Windows 优先 CI 与文档跳过规则

## 本次改动

- 功能分支有代码改动时，默认只运行 Windows Node 22 的完整离线门禁。
- 推送到 `main` 或手动触发 CI 时，继续运行 Linux Node 22/24、macOS，以及两种 Unix 宿主沙箱检查。
- push 或 PR 的改动全部是 Markdown 时，自动 CI 不启动；代码与 Markdown 混合改动仍执行对应门禁。手动触发不受文档过滤影响。
- 在 `AGENTS.md`、`AGENT.md` 和 `docs/testing.md` 说明按改动范围选检查：纯文档提交核对链接与差异，阶段收口再做完整跨平台验证。

## 原因与边界

现有工作集中在 Windows，之前每次提交都会启动六个 CI 任务，纯文档改动也如此。GitHub Actions 消耗运行时间，但离线门禁不调用真实模型，不产生 DeepSeek Token 用量；读取长日志和执行真实模型基准才可能消耗 Agent 上下文或模型 Token。

跨平台能力仍由默认分支和手动 CI 监测。功能分支在合入前若涉及 Unix 行为，应手动运行完整 CI。若将来把 CI 设为 PR 的必需检查，需要重新评估 Markdown 路径过滤，避免纯文档 PR 的必需检查一直等待。

## 实际核验

功能分支的 `b2230ca` 推送触发的 [CI](https://github.com/xilele777/easy-agent/actions/runs/36293131019) 成功：只有 Windows Node 22 执行门禁，其他平台任务跳过。随后单独推送的纯文档提交 `c2c0245` 没有生成新的 CI 运行。
